# DECISIONS.md — judgment calls made while building the booking platform

Format: date · decision · why · how to reverse.

1. **Build inside SAMA-CRM instead of a new repo** (owner's choice, 2026-09-07). One Next.js app, one Supabase project, one Vercel project (`sama-crm`), one WhatsApp webhook. Guest site lives under `src/app/[locale]/(guest)`, back-office screens join the existing CRM `(app)` group.
2. **Keep Next.js 14 / React 18 / Tailwind 3** (the CRM's versions) instead of the prompt's Next.js 15. Upgrading a live app mid-build is the wrong risk to take unsupervised. Nothing in the booking engine needs Next 15.
3. **Two root layouts.** The CRM root layout moved to `src/app/(crm)/layout.tsx` (URLs unchanged) and the guest site gets its own root layout at `src/app/[locale]/layout.tsx` so `<html lang dir>` comes from the URL locale, not the CRM cookie. `next-intl` (v3, Next 14 compatible) handles `/en` `/ar` routing and messages; the CRM keeps its existing cookie-based `useLang()` — the two never mix.
4. **No `bk_guests` table — guests are CRM `contacts`.** The CRM already keys guests by E.164 phone. `bk_bookings.contact_id → contacts.id`; the booking function upserts the contact (name/email/lang/nationality) without touching consent fields.
5. **No `bk_staff` table — staff are CRM `profiles`.** Roles: `super_admin` = admin (everything), `reservation_desk` = front desk (bookings, calendar, blocks, messaging queue; no rates/settings/staff/audit).
6. **`bk_bookings` mirrors into CRM `bookings` by trigger** (same `id`, same `ref`, `room_type` = CRM canonical value, status mapped Confirmed/Cancelled/Completed). Keeps the inbox guest panel, `last_stay` stamping, win-back and birthday automations working. The mirror is additive only (no CRM columns changed).
7. **CRM automations `booking_created`, `pre_arrival`, `post_stay` set to `enabled=false`** to avoid double-messaging — the booking engine now sends confirmation, pre-arrival (3 days before, 10:00) and post-stay (1 day after, 11:00) with the approved Meta templates. `birthday` and `win_back` stay on. Reverse: toggle them back on in `/automations` (and turn off the channel switches in `/settings`).
8. **Room types = the six real ones** from `Hotel Information 2.xlsx`, with `crm_value` equal to the CRM `ROOM_TYPES` strings so both systems agree. Unit split 14/14/14/8/5/5 and rates 50–95 OMR are placeholders (only 60 total and 14 chalets are confirmed).
9. **Taxes:** service charge 8 % and tourism fee 4 % on the room subtotal; VAT 5 % on room + fees (`vat_on_fees` toggle). All rounded to 3 decimals (baisa).
10. **Availability is computed per night** (min over nights of active rooms − room blocks − type stop-sells − overlapping bookings). Double booking prevented with `pg_advisory_xact_lock(hashtext(room_type_id))` inside `bk_create_booking` plus a re-check.
11. **Scheduler = Vercel Cron every 15 min (`vercel.json`, team is on Pro) + pg_cron every 10 min as belt-and-braces**, both hitting `/api/cron/dispatch`. Auth: `Authorization: Bearer <secret>` where the secret is `bk_settings.cron.secret` (generated by migration, readable only via service role) — Vercel Cron sends `CRON_SECRET` env if set; either is accepted. This avoids needing new Vercel env vars for the scheduler.
12. **Booking-page tokens** are HMAC-SHA256 of the ref keyed by `BOOKING_TOKEN_SECRET` if set, else derived from `SUPABASE_SERVICE_ROLE_KEY` (already secret, already on Vercel).
13. **Hotel contact details, links and review URLs live in `bk_settings`** (editable in `/settings`), not env vars. Env only holds credentials.
14. **Email templates are hand-built HTML** (inline styles, bilingual per guest's preferred language) instead of React Email — fewer dependencies, same result, matches the CRM's existing email shell.
15. **WhatsApp bodies** match Section 5 of the kickoff prompt variable-for-variable. Dates in messages are formatted `Fri 12 Sep 2026` (EN) / Arabic long date (AR); totals as `123.500`.
16. **Photos**: the owner's Website/Pictures folder was resized to ≤1800 px and committed under `public/images/` (hero, rooms, facilities). Types without photos (Sama Suites) reuse Deluxe/Chalet shots and are flagged in HANDOFF.md.
17. **Booking refs** use `SAMA-YY-XXXXXX` (6 unambiguous alphanumerics), compatible with the CRM's `SAMA-YY-…` convention.
18. **Rate-limit** on the public booking action: in-memory token bucket per IP, 10/min per instance (good enough on Vercel; noted in HANDOFF).
